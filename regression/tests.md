## 001. project export lowercases APEXlang file and folder names

P2 bug, area `export`.

- **readable mode:** Introduced: 26.1.2; fixed: –; last failed: 26.3.0
- **apexlang mode:** Introduced: 26.1.2; fixed: –; last failed: 26.3.0
- **Oracle status:** not confirmed
- **Sources:** [Forum post](https://forums.oracle.com/ords/apexds/post/sqlcl-project-export-lowercases-apexlang-file-and-folder-na-5571), [Documentation](../docs/10.1-sqlcl_project_bugs.md#new-sqlcl-2612--apexlang-bugs)
- **Workaround:** Run `apex export -applicationid <id> -exptype APEXLANG -dir src/database/<schema>/apex_apps/f<id> -f` after `project export`.
- **How it is tested:** Remove the exported application folder, run `project export -o APEX.<app_id>` in the test repo, and compare every mixed-case file or folder name of the baseline export with the exported names.
- **Passes when:** Every mixed-case name in the baseline export (for example static-files/img/mixedCaseImageName.webp) is exported with the same case.
- **Script:** [issues/001/test.sh](issues/001/test.sh)

## 016. stage.change.changeStyle=multiple puts each staged statement in its own changeset

P2 feature, area `stage`.

- **Versions:** Introduced: –; fixed: 26.1.2; last failed: 26.3.0
- **Oracle status:** setting confirmed on the forum; to be exposed through project config as the fix of the logged bug
- **Sources:** [Forum post](https://forums.oracle.com/ords/apexds/post/sqlcl-project-please-split-ddl-statements-in-a-file-into-lo-8780), [Documentation](../docs/10.2.-sqlcl_project_enhancements.md#21-split-ddl-statements-in-a-file-into-logical-changesets)
- **Workaround:** Add "change": {"changeStyle": "multiple"} to the stage object in .dbtools/project.config.json.
