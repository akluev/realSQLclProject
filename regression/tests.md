## 001. project export lowercases APEXlang file and folder names

P2 bug, area `export`. Introduced: 26.1.2; fixed: –; last failed: 26.2.2.

- **Oracle status:** not confirmed
- **Sources:** [Forum post](https://forums.oracle.com/ords/apexds/post/sqlcl-project-export-lowercases-apexlang-file-and-folder-na-5571), [Documentation](../docs/10.1-sqlcl_project_bugs.md#new-sqlcl-2612--apexlang-bugs)
- **Workaround:** Run `apex export -applicationid <id> -exptype APEXLANG -dir src/database/<schema>/apex_apps/f<id> -f` after `project export`.
- **How it is tested:** Remove the exported application folder, run `project export -o APEX.<app_id>` in the test repo, and compare every mixed-case file or folder name of the baseline export with the exported names.
- **Passes when:** Every mixed-case name in the baseline export (for example static-files/img/mixedCaseImageName.webp) is exported with the same case.
- **Script:** [issues/001/test.sh](issues/001/test.sh)

## 007. project export -o APEX.&lt;id> exports users and data that were not requested

P1 bug, area `export`. Introduced: 26.2; fixed: –; last failed: 26.2.2.

- **Oracle status:** reported
- **Sources:** [Forum post](https://forums.oracle.com/ords/apexds/post/apex-app-project-export-is-exporting-application-dml-data-a-4157), [Article](https://alexonapex.com/blog/2026/09/11/sqlcl-project-26-2-2-two-apexlang-directory-structures-one-migration-blocker/#unexpected-exports-and-undiscoverable-configuration), [Documentation](../docs/10.1-sqlcl_project_bugs.md#new-sqlcl-262-bugs)
- **Workaround:** Add `export_type != 'TABLES_DML'` and `export_type != 'ALL_USERS'` to .dbtools/filters/project.filters (the test project keeps them between --TEST-007 BEGIN and --TEST-007 END).

Restore src, export with `project export -o APEX.<app_id>` and list src files changed outside the application folder: with the workaround there should be none. Then remove the block, restore src, export again and list them again: that second list decides the result. Seen with any -o export in SQLcl 26.2.2 (e.g. -o <package> also exported 14 users), not only APEX applications.
- **Passes when:** Without the TEST-007 filters, nothing outside src/database/<schema>/apex_apps/ changes.
- **Script:** [issues/007/test.sh](issues/007/test.sh)

## 017. Staged changesets use backslashes in logicalFilePath on Windows

P2 bug, area `stage`. Introduced: –; fixed: –; last failed: 26.2.2.

- **Oracle status:** the APEX controller case was fixed in 26.2.0 (Omar Bakhir-Oracle, Mar 30 2026); other changesets still use \
- **Sources:** [Forum post](https://forums.oracle.com/ords/apexds/post/sqlcl-25-4-1-project-windows-apex-changesets-redeployed-eve-3997)
- **Workaround:** Stage on one OS only, or fix the paths in dist before committing.

Only meaningful on Windows.
